# 🧭 MD Operations Dashboard
> 라이선스 브랜드 쿠팡 채널 운영 의사결정 지원 대시보드 (Python / Streamlit)

🔗 **Live Demo:** https://md-dashboard-choieuntae.streamlit.app/

---

## 📌 프로젝트 배경

라이선스 브랜드 쿠팡 채널 MD로 근무하며 반복 수행하던 4가지 핵심 업무 —
**재고 현황 관리, OOS(품절) 대응, ASP 가격 모니터링, 성과 추적** — 의 의사결정
로직을 정량 지표 기반 시스템으로 재설계하고, 하나의 대시보드로 통합 구현했습니다.

> ⚠️ 본 프로젝트는 실제 업무 프로세스의 로직을 일반화한 포트폴리오입니다.
> 모든 데이터는 시뮬레이션이며, 실제 기업 정보를 포함하지 않습니다.
> 실제 담당 브랜드는 6개이나, 대시보드에서는 구조 설명을 위해 2개로 단순화했습니다.

## 🗂 구성

### 1️⃣ OOS 발주관리
쿠팡 FC 재고와 물류 직영 재고, 최근 14일 평균 판매량을 기반으로 SKU별 **품절 예상일**과
**발주 여유일수**를 자동 계산하여 품절/긴급/주의/안전 4단계로 분류합니다.

```
소진율       = (쿠팡총납품수량 − 쿠팡FC현재고) ÷ 쿠팡총납품수량
품절예상일수 = 쿠팡FC현재고 ÷ 일평균판매량(최근14일)
발주여유일수 = 품절예상일수 − 리드타임
```

> 실무에서는 쿠팡 FC 재고·자사 물류 재고·소진율을 **절대값 기준**(FC 10개 이하 /
> 물류 10개 이상 / 소진율 60% 이상)으로 필터링해 재입고 대상을 선별합니다.
> 다만 이 방식은 SKU별 판매 속도 차이를 반영하지 못하는 한계가 있어, 본 대시보드에서는
> 판매 속도와 리드타임을 반영한 **동적 기준**으로 개선안을 설계했습니다.

### 2️⃣ 매출·입고 추이
담당 시작 시점부터 브랜드별 월별 매출액, 입고수량, OOS율 변화를 추적합니다.

### 3️⃣ ASP 가격 모니터링
쿠팡 광고센터에서 수집한 PI별 전 옵션 가격으로 최저가/최고가를 산출하고, 최초 등록
ASP와 비교해 가격 이탈 여부를 판정합니다. 이탈 발생 시 네이버 쇼핑 전 채널을 전수조사해
원인(타 채널 저가 노출 / 쿠팡 자동 가격조정)을 자동 분류합니다.

```
최저가 < ASP                 → 최종가 = 최저가
최저가 = ASP, 최고가 > ASP   → 최종가 = 최고가
최저가 > ASP, 최고가 > ASP   → 최종가 = 최고가
최종가 ≠ ASP                 → 오류 → 원인 진단
```

### 4️⃣ 브랜드별 운영지표
매출 성장률, OOS율 개선폭, 재고 안전 비율, ASP 준수율 4개 지표로 브랜드별 운영 현황을
비교합니다. 지표별 단위와 척도가 달라 하나의 종합 점수로 합산하지 않고 개별 지표로
제시합니다.

## 🔗 실제 업무 자동화와의 연결

이 대시보드는 실제 업무에서 구현한 자동화 도구들의 로직을 통합 시각화한 것입니다.

| 실제 자동화 | 효과 | 대시보드 반영 |
|---|---|---|
| VBA 재고리스트 매크로 | 2시간 → 20분 | OOS 탭 데이터 구조 |
| Selenium 쿠팡 가격 수집 | 4~5시간 → 1시간 | ASP 탭 최저가/최고가 산출 |
| 네이버 쇼핑 전수 모니터링 | 가격 이탈 원인 자동 진단 | ASP 탭 원인 분류 로직 |

> 네이버 쇼핑은 기존 API 방식으로 운영하다 API 제공 중단 이후 크롤링 기반으로 전환했습니다.
